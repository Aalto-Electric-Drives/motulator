class motulator.common.model.CarrierComparison(N=2**12, t_d=0.0)[source]#

Bases: PWM

Carrier comparison.

This computes the gate signals and their durations based on the duty ratios. Instead of searching for zero crossings, the switching instants are explicitly computed in the beginning of each sampling period, allowing faster simulations. The dead time delays the turn-on of the switches, i.e., each leg is blanked for t_d after its switching instant.

Parameters:

  • N (int, optional) – Amount of the counter quantization levels, defaults to 2**12.

  • t_d (float, optional) – Dead time (s), defaults to 0.

Examples

>>> from motulator.common.model import CarrierComparison
>>> carrier_cmp = CarrierComparison()
>>> # First call gives rising edges
>>> t_steps, q_abc, _ = carrier_cmp(1e-3, [.4, .2, .8])
>>> # Durations of the switching states
>>> t_steps
array([0.00019995, 0.00040015, 0.00019995, 0.00019995])
>>> # Switching states
>>> q_abc
array([[0, 0, 0],
       [0, 0, 1],
       [1, 0, 1],
       [1, 1, 1]])
>>> # Second call gives falling edges
>>> t_steps, q_abc, _ = carrier_cmp(1e-3, [.4, .2, .8])
>>> t_steps
array([0.00019995, 0.00019995, 0.00040015, 0.00019995])
>>> q_abc
array([[1, 1, 1],
       [1, 0, 1],
       [0, 0, 1],
       [0, 0, 0]])
>>> # Sum of the step times equals T_s
>>> float(np.sum(t_steps))
0.001
>>> # Dead time blanks each leg after its switching instant
>>> carrier_cmp = CarrierComparison(t_d=1e-4)
>>> t_steps, q_abc, b_abc = carrier_cmp(1e-3, [.5, .5, .5])
>>> np.round(t_steps / 1e-3, 3)  # In ms
array([0.5, 0.1, 0.4])
>>> q_abc
array([[0, 0, 0],
       [0, 0, 0],
       [1, 1, 1]])
>>> b_abc
array([[0, 0, 0],
       [1, 1, 1],
       [0, 0, 0]])
class motulator.common.model.CompositeModel(models)[source]#

Bases: motulator.common.model._base.System

Composite of models sharing subsystems.

The models are coupled through shared subsystem objects, e.g., a DC bus given to the models of a grid converter and a drive. Each model keeps its converter, PWM model, and computational delay, and it is driven by its own control system in the simulation, see Simulation. The subsystems are evaluated in the order of the models, a shared subsystem at its first occurrence. The order is not resolved automatically: a shared subsystem whose outputs other subsystems depend on directly must come first in each model, as Model places the DC bus.

Parameters:

models (dict[str, Model]) – Models by name, each with its own converter. The names are used for the control systems and the results, so they must be valid attribute names (not starting with an underscore, and not t).

class motulator.common.model.DCBus(C_dc, u_dc, converters)[source]#

Bases: motulator.common.model._base.Subsystem

Capacitive DC bus feeding converters.

The DC bus feeds the given converters, whose DC currents are computed from their switching states and AC currents. The DC-bus voltage is connected to the input u_dc of each converter by the model (see Model). The DC bus can be shared by the converters of several models (see CompositeModel). An external current, e.g., from a battery or a braking chopper, can also be fed to the DC bus.

Parameters:

  • C_dc (float) – DC-bus capacitance (F).

  • u_dc (float) – Initial DC-bus voltage (V).

  • converters (Sequence[VoltageSourceConverter]) – Converters fed from the DC bus.

class motulator.common.model.Model(converter, subsystems, connections, pwm=False, delay=0, dc_bus=None)[source]#

Bases: System

Base class for system models with a converter driven by a control system.

The converter subsystem gets the switching state q_c_ab, which is held constant over each integration interval. The PWM model includes the dead time converter.t_d, and the computational delay is sized according to the number of legs converter.n_legs.

Parameters:

  • converter (Converter) – Converter model.

  • subsystems (list[Subsystem]) – All subsystems, including the converter.

  • connections (dict[tuple[Subsystem, str], tuple[Subsystem, str]]) – Connections as {(target, input_name): (source, output_name)}.

  • pwm (bool, optional) – Enable PWM model, defaults to False.

  • delay (int, optional) – Computational delay (samples), defaults to 0.

  • dc_bus (DCBus, optional) – DC bus feeding the converter, whose input u_dc is connected to the DC-bus voltage. The DC bus is added to the subsystems, and it can be shared with other models, see CompositeModel. Defaults to None, in which case the converter has its own DC-bus model (or a constant DC-bus voltage).

class motulator.common.model.Sensor[source]#

Sensor with a gain error, an offset, and additive Gaussian noise.

The measured signal is y = gain*x + offset + std*n, where x is the actual signal and n is zero-mean white Gaussian noise with unit variance, drawn independently for each channel at each sample. The parameters are scalars or arrays with one element per channel (e.g., per phase), in the units of the measured signal. The noise represents the sampled signal, i.e., std is the standard deviation of the samples after the anti-aliasing filter and the A/D conversion.

Parameters:

  • gain (array_like, optional) – Gain, defaults to 1.

  • offset (array_like, optional) – Offset, defaults to 0.

  • std (array_like, optional) – Standard deviation of the noise, defaults to 0.

  • rng (numpy.random.Generator, optional) – Random number generator, defaults to an unseeded generator. For reproducible results, pass the same seeded generator to all sensors. Sensors with separate generators of the same seed would produce identical noise.

Examples

>>> from motulator.common.model import Sensor
>>> sensor = Sensor(gain=[1.02, 1, 1], offset=[0, 0.1, 0])
>>> sensor([1.0, -0.5, -0.5])
array([ 1.02, -0.4 , -0.5 ])
class motulator.common.model.Simulation(mdl, ctrl, show_progress=True, cfg=None, t_start=None)[source]#

Simulation environment.

Each control system is called at its own sampling instants, which gives the sampling period of its next control cycle. The control systems of a composite model can have different sampling periods, and their sampling instants need not coincide. The switching states of the converters are held constant between the sampling and switching instants of all the converters.

Parameters:

  • mdl (Model | CompositeModel) – Continuous-time system model.

  • ctrl (ControlSystem | Mapping[str, ControlSystem]) – Discrete-time control system. For a composite model, the control systems of the models by the model names.

  • show_progress (bool, optional) – Show progress during simulation, defaults to True.

  • cfg (SolverCfg, optional) – Solver configuration parameters.

  • t_start (float | Mapping[str, float], optional) – First sampling instant (s) of the control system or, for a composite model, of the control systems by the model names. The time ctrl.t of the control system is set to this value. Defaults to the initial time of the model, as do the control systems not included in the mapping, in which case ctrl.t is not changed.

simulate(t_stop=1.0, N_eval=0)[source]#

Solve continuous-time system model and call control system.

The simulation runs until the first sampling instant after t_stop. A subsequent call continues the simulation.

Parameters:

  • t_stop (float, optional) – Simulation stop time, defaults to 1.

  • N_eval (int, optional) – Number of evenly spaced data points to be returned by the solver for each integration interval, i.e., for each interval between the sampling and switching instants. Defaults to 0, in which case the number and spacing of points is selected by the solver.

Return type:

class motulator.common.model.Subsystem[source]#

Bases: Protocol

Protocol defining the interface for all subsystems.

This class defines the interface for all subsystems. It is a generic class that can be used with different input, output, state, and history types. The class provides methods for setting states, outputs, and computing state derivatives. It also provides methods for extending the state history and creating time-series representations of the subsystem. The state history is a dict of lists, keyed by the names of the state fields. The model initializes it by init_state_history and extends it by extend_state_history.
