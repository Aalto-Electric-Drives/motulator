class motulator.drive.model.CarrierComparison(t_d=0.0, delay=None, single_update=False, N=2**12)[source]#

Bases: TwoLevelModulator[collections.abc.Sequence[float]]

Carrier comparison of a voltage-source converter.

This computes the gate signals and their durations based on the duty ratios. Instead of searching for zero crossings, the switching instants are explicitly computed in the beginning of each half carrier period, allowing faster simulations. The dead time delays the turn-on of the switches, i.e., each leg is blanked for t_d after its switching instant.

Parameters:

  • t_d (float, optional) – Dead time (s), defaults to 0.

  • delay (int, optional) – Computational delay in half carrier periods, defaults to one sampling period, see Modulator.

  • single_update (bool, optional) – Sample and update the duty ratios once per carrier period, defaults to False, see Modulator.

  • N (int, optional) – Amount of the counter quantization levels, defaults to 2**12.

Examples

>>> from motulator.common.model import CarrierComparison
>>> carrier_cmp = CarrierComparison(delay=0)
>>> # First call gives rising edges
>>> t_steps, gates = carrier_cmp(1e-3, [.4, .2, .8])
>>> # Durations of the switching states
>>> t_steps
array([0.00019995, 0.00040015, 0.00019995, 0.00019995])
>>> # Gate signals of the upper switches
>>> gates[:, 0]
array([[0, 0, 0],
       [0, 0, 1],
       [1, 0, 1],
       [1, 1, 1]])
>>> # Second call gives falling edges
>>> t_steps, gates = carrier_cmp(1e-3, [.4, .2, .8])
>>> t_steps
array([0.00019995, 0.00019995, 0.00040015, 0.00019995])
>>> gates[:, 0]
array([[1, 1, 1],
       [1, 0, 1],
       [0, 0, 1],
       [0, 0, 0]])
>>> # Sum of the step times equals T_s
>>> float(np.sum(t_steps))
0.001
>>> # Dead time blanks each leg after its switching instant
>>> carrier_cmp = CarrierComparison(t_d=1e-4, delay=0)
>>> t_steps, gates = carrier_cmp(1e-3, [.5, .5, .5])
>>> np.round(t_steps / 1e-3, 3)  # In ms
array([0.5, 0.1, 0.4])
>>> gates[:, 0]  # Gate signals
array([[0, 0, 0],
       [0, 0, 0],
       [1, 1, 1]])
>>> gates[:, 1]  # Blanking signals
array([[0, 0, 0],
       [1, 1, 1],
       [0, 0, 0]])

Compute the gate signals and their durations.

Parameters:

  • T_half (float) – Half carrier period (s).

  • command (Sequence[float], shape (n_legs,)) – Duty ratios in the range [0, 1].

Returns:

  • t_steps (SwitchingTimes, shape (N,)) – Durations of the intervals (s).

  • gates (GateStates, shape (N, 2, n_legs)) – Gate signals of the upper switches and blanking signals in each interval.

Return type:

tuple[SwitchingTimes, GateStates]

Notes

Simultaneous switching instants are merged, so the number of intervals varies. Blanking continues across half carrier periods, including changes in their length. A reversed command cancels a pending turn-on and starts a new blanking interval. On the first call, the initial commanded state is assumed to already conduct.

class motulator.drive.model.CompositeModel(models)[source]#

Bases: motulator.common.model._base.Model[None]

Composite of models sharing subsystems.

The models are coupled through shared subsystem objects, e.g., a DC bus given to the models of a grid converter and a drive. Each model keeps its converter, whose modulator includes the PWM model and the computational delay, and the model of a controlled converter is driven by its own control system in the simulation, see Simulation. A shared subsystem is evaluated once, whatever its names in the models (the composite names the subsystems model.subsystem after their first occurrence), in the order derived from the direct dependencies, see Model.

Parameters:

models (dict[str, Model]) – Models by name. The names are used for the control systems and the results, so they must be valid attribute names (not starting with an underscore, and not t).

class motulator.drive.model.DCBus(C_dc, u_dc)[source]#

Bases: motulator.common.model._base.Subsystem

Capacitive DC bus feeding converters.

The DC bus feeds the converters of the models it is given to, see Model. The model connects its converter to the DC bus through connect, which registers the converter in converters and gives the connections of its DC terminals, i.e., the DC-bus voltage to the input u_dc of the converter. The DC bus draws the DC currents of the registered converters, computed from their switching states and AC currents. The DC bus can be shared by the converters of several models, see CompositeModel. An external current, e.g., from a battery or a braking chopper, can also be fed to the DC bus.

Parameters:

  • C_dc (float) – DC-bus capacitance (F).

  • u_dc (float) – Initial DC-bus voltage (V).

Continuous-time system model for a machine connected directly to the grid.

The stator terminals of the machine are connected to a three-phase voltage source, e.g., to model the direct-on-line start of an induction machine. A series grid impedance can be lumped into the machine parameters, e.g., into the stator resistance and the leakage inductance of the inverse-Γ model of an induction machine.

Parameters:

  • machine (InductionMachine | SynchronousMachine) – Electric machine model.

  • mechanics (MechanicalSystem | TwoMassMechanicalSystem | ExternalRotorSpeed) – Mechanical system model.

  • ac_source (ThreePhaseSource) – Three-phase voltage source.

class motulator.drive.model.InductionMachine(par, i_s_sensor=None)[source]#

Bases: motulator.common.model.Subsystem

Γ-equivalent model of an induction machine.

An induction machine is modeled using the Γ-equivalent model [1]. The stator inductance L_s can either be constant or a function of the stator flux magnitude:

L_s = L_s(abs(psi_s_ab))

Optionally, eddy-current core losses can be modeled by means of a constant core-loss conductance G_c, connected in parallel with the magnetizing branch.

Parameters:

  • par (InductionMachinePars | InductionMachineInvGammaPars) – Machine parameters. Core losses are modeled if par.G_c is nonzero.

  • i_s_sensor (Sensor, optional) – Phase-current sensors, defaults to an ideal measurement.

Notes

The Γ model is chosen here since it can be extended with the magnetic saturation model in a straightforward manner. If the magnetic saturation is omitted, the Γ model is mathematically identical to the inverse-Γ and T models [1].

The core-loss branch is located between the stator resistance and the magnetizing inductance, i.e., the voltage across G_c is u_s_ab - R_s*i_s_ab. Consequently, the stator current depends directly on the stator voltage. This algebraic loop is solved in a closed form. The electromagnetic torque is produced by the current flowing into the magnetic circuit, i.e., the core-loss current is excluded from the torque.

References

[1] (1,2)

Slemon, “Modelling of induction machines for electric drives,” IEEE Trans. Ind. Appl., 1989, https://doi.org/10.1109/28.44251

class motulator.drive.model.InductionMachinePars[source]#

Γ-model parameters of an induction machine.

This contains Γ-model parameters of an induction machine. The main-flux saturation can also be modeled by providing a callable L_s parameter. For convenience, the class also provides the corresponding inverse-Γ model parameters, which can be used in control systems. If the saturation is modeled, these inverse-Γ parameters depend on the stator flux linkage magnitude psi_s that should be updated by calling the update_psi_s method.

Parameters:

  • n_p (int) – Number of pole pairs.

  • R_s (float) – Stator resistance (Ω).

  • R_r (float) – Rotor resistance (Ω).

  • L_ell (float) – Leakage inductance (H).

  • L_s (float | Callable[[float], float]) – Stator inductance (H). If callable, it should be a function of the stator flux linkage magnitude (Vs).

  • G_c (float, optional) – Core-loss conductance (S), modeled in parallel with the magnetizing branch, defaults to 0 (no core losses).

  • psi_s (float, optional) – Stator flux linkage magnitude (Vs), at which the callable L_s is evaluated, defaults to 0. It can be updated by calling the update_psi_s method.

class motulator.drive.model.Sensor[source]#

Sensor with a gain error, an offset, and additive Gaussian noise.

The measured signal is y = gain*x + offset + std*n, where x is the actual signal and n is zero-mean white Gaussian noise with unit variance, drawn independently for each channel at each sample. The parameters are scalars or arrays with one element per channel (e.g., per phase), in the units of the measured signal. The noise represents the sampled signal, i.e., std is the standard deviation of the samples after the anti-aliasing filter and the A/D conversion.

Parameters:

  • gain (array_like, optional) – Gain, defaults to 1.

  • offset (array_like, optional) – Offset, defaults to 0.

  • std (array_like, optional) – Standard deviation of the noise, defaults to 0.

  • rng (numpy.random.Generator, optional) – Random number generator, defaults to an unseeded generator. For reproducible results, pass the same seeded generator to all sensors. Sensors with separate generators of the same seed would produce identical noise.

Examples

>>> from motulator.common.model import Sensor
>>> sensor = Sensor(gain=[1.02, 1, 1], offset=[0, 0.1, 0])
>>> sensor([1.0, -0.5, -0.5])
array([ 1.02, -0.4 , -0.5 ])

class motulator.drive.model.SynchronousMachine(par, i_s_sensor=None)[source]#

Bases: motulator.common.model.Subsystem

Synchronous machine model.

This model is internally represented in rotor coordinates, which results in the simplest implementation. The interfaces are in stator coordinates. The magnetic saturation can be modeled by providing a nonlinear current map, either as i_s_dq_fcn in SaturatedSynchronousMachinePars or, including spatial harmonics, as magnetic_map_fcn in SpatialSaturatedSynchronousMachinePars. Optionally, eddy-current core losses can be modeled by means of a constant core-loss conductance G_c, connected in parallel with the magnetizing branch.

Parameters:

  • par (SynchronousMachinePars | SaturatedSynchronousMachinePars | SpatialSaturatedSynchronousMachinePars) – Machine parameters. Core losses are modeled if par.G_c is nonzero.

  • i_s_sensor (Sensor, optional) – Phase-current sensors, defaults to an ideal measurement.

Notes

The core-loss branch is located between the stator resistance and the magnetizing branch, i.e., the voltage across G_c is u_s - R_s*i_s. Consequently, the stator current depends directly on the stator voltage. This algebraic loop is solved in a closed form. The electromagnetic torque is produced by the current flowing into the magnetic circuit, i.e., the core-loss current is excluded from the torque.

class motulator.drive.model.VoltageSourceConverter(u_dc=None, modulator=None, u_th=0.0, sign=np.sign, u_dc_sensor=None)[source]#

Bases: DiodeBridge, motulator.common.model._base.ControlledConverter

Three-phase voltage-source converter.

The modulator converts the duty ratios of the control system into the gate states of the legs, i.e., the gate signals of the upper switches and the blanking signals, including the computational delay and the dead time, see ZOH and CarrierComparison. The switches are ideal, except for the dead time and the threshold voltage. When a leg is blanked, i.e., neither of its switches conducts, the current direction determines which diode conducts. The leg state is then (1 - sign(i))/2, where i is the phase current in the beginning of the blanking interval. The threshold voltage of the conducting device, assumed equal for the switches and the diodes, reduces each phase voltage by u_th*sign(i), where the current direction is also determined at the latest switching instant. A current within the tolerance of the diode-state transitions has no direction, see current_direction. The DC-bus voltage is the input u_dc, which is constant unless a DC-bus model is connected to it (see DCBus and Model).

When the gates are blocked (inp.enabled is False), all the switches are open, and the converter operates as a diode bridge, see DiodeBridge. The diode states are latched from the current directions when the gates are blocked.

Parameters:

  • u_dc (float, optional) – Constant DC-bus voltage (V). Defaults to None, in which case the converter must be fed from a DC-bus model.

  • modulator (TwoLevelModulator, optional) – Modulator converting the command of the control system into the gate states, see TwoLevelModulator. Defaults to ZOH(), i.e., the switching-cycle averaged model of the duty ratios without the dead time and with the computational delay of one sampling period. A modulator keeps its state, so each converter needs its own.

  • u_th (float, optional) – Threshold voltage (V) of the power devices, defaults to 0.

  • sign (Callable[[np.ndarray], np.ndarray], optional) – Function of the phase currents (A) determining the leg states during blanking, defaults to np.sign. A smooth function, such as 2/pi*arctan(i/i_d), can be used to model the effect of parasitic capacitances, for example.

  • u_dc_sensor (Sensor, optional) – DC-bus voltage sensor, defaults to an ideal measurement.

class motulator.drive.model.ZOH(t_d=0.0, delay=None, single_update=False)[source]#

Bases: TwoLevelModulator[collections.abc.Sequence[float]]

Zero-order hold of the duty ratios of a voltage-source converter.

The dead time reduces the gate signal duty ratios of both switches of a leg by t_d/(2*T_half), leaving the leg blanked for the fraction t_d/T_half of the half carrier period T_half, unless the leg does not switch. Short pulses are suppressed, and the blanking fraction is computed from the remaining on-times of both switches. This is a switching-cycle averaged model, not a model of switching transients.

Parameters:

  • t_d (float, optional) – Dead time (s), defaults to 0.

  • delay (int, optional) – Computational delay in half carrier periods, defaults to one sampling period, see Modulator.

  • single_update (bool, optional) – Sample and update the duty ratios once per carrier period, defaults to False, see Modulator.
